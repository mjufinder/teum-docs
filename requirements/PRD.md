## 1. 한 줄 요약

에브리타임 시간표 이미지를 올리면 팀원 전원의 공강을 **비트 연산으로 즉시 계산**해 최적 회의 시간 Top 3를 추천하고, **투표 → 재검사 → 확정 → 공유**까지 한 번에 끝내는 대학생용 일정 조율 웹 서비스.

## 2. 문제 정의

| 현재 방식 | 페인포인트 |
|---|---|
| 단체방에 시간표 캡처 공유 후 눈으로 대조 | 느리고, 실수·누락이 잦음 |
| When2meet 등 기존 도구 | 이미 있는 시간표를 **다시 옮겨 적는 이중 입력** |
| 메신저로 의견 수렴 | 일정 충돌·의사소통 지연, 결론이 흐지부지됨 |

**Teum의 해법**
1. **데이터 재활용** — 기존 시간표 이미지(OCR) 가져오기 + 수기 보완
2. **알고리즘 매칭** — 비트 벡터 AND 연산으로 공통 공강 즉시 추출
3. **원스톱 조율** — 추천 → 투표 → 최신 시간표 재검사 → 확정 → 공유 링크

## 3. 목표 & 성공 지표

| 목표 | 성공 지표 (검증 기준) |
|---|---|
| 조율 시간 단축 | 수십 분 걸리던 조율을 **수 초 내 추천**으로 단축 (실사용 소요 시간 비교) |
| 확장성 | 인원(N) 증가에도 핵심 연산 O(N) 유지, **수 초 이내 응답** |
| 정확성 | 기준 구현(슬롯 순회) 결과와 **100% 일치**, 정의된 테스트케이스 전부 통과 |
| 편의성 | 컬러맵 색상과 실제 참석 가능 인원 일치, E2E 흐름 끊김 없음 |
| 완료 기준 | **로그인 → 모임 생성 → 시간표 입력 → 매칭 → 투표 → 확정 → 공유** E2E 시연 성공 |

## 4. 사용자 & 역할

**주요 사용자**: 팀 프로젝트·전공 스터디·동아리 등으로 회의 시간 조율이 잦은 대학생 그룹

| 역할 | 할 수 있는 일 |
|---|---|
| 사용자 (User) | 소셜 로그인, 프로필·시간표 등록/수정, 모임 생성·참여, 회원 탈퇴 |
| 모임 구성원 (Member) | 메모 작성, 후보 투표, 결과 조회·공유, 모임 탈퇴 |
| 모임 관리자 (Admin) | 모임 정보 수정·삭제, 팀원 추가, 재계산, 최종 확정, 권한 위임 |
| 비회원 (Guest) | 공유 링크로 **확정 일정 읽기 전용 조회** |

- 관리자는 별도 클래스가 아니라 `MEETING_MEMBER.role = ADMIN`으로 구분
- 모임 생성자 = 기본 관리자, **관리자는 모임당 1명**

## 5. 범위 (Scope)

| 구분 | 기능 |
|---|---|
| **MVP (이번 학기 구현)** | 소셜 로그인/로그아웃, 프로필, 가입 온보딩, 시간표 입력(OCR + 수기), 비트 벡터 변환, 모임 생성/수정/삭제, 팀원 추가, 자동 공강 매칭 + Top 3 추천, 참석률 컬러맵, 메모, 모임 탈퇴/권한 위임, 최종 일정 확정(재검사 포함), 결과 링크 공유 |
| **MVP 포함 (요구사항 명세서 기준 상향)** | 차선책 제시(MATCH-03), 후보 선호 투표·집계(VOTE-01~02) |
| **설계만** | 세부 멤버 권한 관리 |
| **향후 확장** | 알림, 외부 캘린더 내보내기, 결과 화면 이미지 저장, 자연어 이동시간 입력(AI 해석) |
| **명시적 제외** | 별도 프로그램 설치(웹 전용), 공유 화면에 개인 상세 시간표 노출 |

> ⚠️ 개념설계서에서는 차선책=향후, 투표=설계만이었으나 요구사항 명세서에서 우선순위 '상'으로 올라감 → §14-3 참고

## 6. 핵심 사용자 흐름

```
[소셜 로그인] ─ 기존 회원 ─────────────────────────────┐
     │ 신규                                             ▼
[온보딩: 이름·전공 + 시간표(OCR/수기) 필수] ──▶ [메인]
                                                       │
                     [모임 생성: 이름 + 최소 회의시간] ◀┘
                                  │
                     [팀원 ID 검색·추가 (즉시 등록)]
                                  │  ← 추가될 때마다 자동 매칭
                     [추천 Top 3 / 차선책 + 컬러맵]
                                  │
                     [구성원 선호 투표 (1인 1표)]
                                  │
                     [관리자: 최신 시간표 재검사 → 확정]
                                  │
                     [확정 일정 조회 + 외부 공유 링크(비회원 읽기 전용)]
```

**예시 시나리오**: 팀원 3명이 각자 시간표 등록 → 관리자가 모임 생성 후 2명 추가 → 화 15:00–16:00 포함 후보 3개 추천 → 투표로 화 15–16시 최다 득표 → 관리자가 재검사 후 확정 → 링크 공유

## 7. 기능 요구사항

우선순위: **상** = MVP 필수 / **중** = MVP 권장 / **하** = 여유 시

### 7.1 회원/인증 (AUTH)

| ID | 요구사항 | 상세 | 수용 기준 (Acceptance Criteria) | 우선 |
|---|---|---|---|---|
| AUTH-01 | 소셜 로그인 | OAuth 2.0 기반 소셜 계정 간편 로그인·가입 | 기존 계정 → 메인 이동 / 신규 계정 → 온보딩 이동. 계정은 `(provider, provider_user_id)` 복합 유니크로 식별 | 상 |
| AUTH-02 | 가입 온보딩 | 이름·전공 + 시간표 등록(OCR/수기) 완료 시 가입 완료 | 필수 프로필 또는 시간표 미입력 시 가입 완료 불가. 완료 후 `profile_completed = true` | 상 |
| AUTH-03 | 회원 탈퇴 | 개인정보·시간표 Soft Delete (`deleted_at`) | 유일한 관리자인 모임이 있으면 **권한 위임 또는 모임 삭제 후** 탈퇴 가능 | 중 |
| AUTH-04 | 로그아웃 | 현재 세션 종료 | 로그아웃·로그인 실패 시 인증 상태 정상 처리 | 상 |
| AUTH-05 | 프로필 조회/수정 | 이름·전공 확인·수정 | 마이페이지에서 수정 가능 | 상 |

### 7.2 시간표 관리 (TIME)

| ID | 요구사항 | 상세 | 수용 기준 | 우선 |
|---|---|---|---|---|
| TIME-01 | 시간표 이미지 인식(OCR) | 에브리타임 시간표 이미지(PC/모바일) 업로드 → 수업 일정 자동 추출 | 고정 템플릿(에브리타임 다운로드 이미지) 기준으로 좌표→일정 정제. **인식 실패/오류 시 수기 수정 화면 제공**. 저장 전 사용자 확인 단계 필수 | 상 |
| TIME-02 | 수기 등록·수정 | 요일·시작/종료 시각·과목명 직접 입력 (온보딩/마이페이지). 강의 외 개인 일정(알바·과외 등)도 등록 | `시작 ≥ 종료` 입력 차단(DB CHECK 제약 포함), 본인 기존 일정과 겹치면 차단. 드래그/터치 기반 슬롯 선택 UI | 상 |
| TIME-03 | 비트 벡터 변환 | 일정 → 주간 120슬롯 가능(1)/불가능(0) 비트열로 규격화 | 일정 0건 사용자 = '전원 공강' 정식 벡터 생성. **미등록 사용자와 반드시 구분** | 상 |
| TIME-04 | 시간표 변경 반영 | 시간표 수정 시 버전 증가 + 소속 모임 재계산 플래그 | 같은 트랜잭션에서 `timetable_version += 1`, 소속 모임 `needs_recalc = true` | 상 |

|---|---|---|---|---|
| MEET-01 | 모임 생성 | 모임 이름 + 최소 회의시간 설정 | 주간(1주) 고정 기준으로 연산. 생성자는 자동 ADMIN | 상 |
| MEET-02 | 모임 정보·조건 수정 | 이름·최소 회의시간 수정 | 진행 중 투표가 있으면 **경고 후** 기존 후보 묶음 폐기(`vote_status = 폐기`) | 상 |
| MEET-03 | 팀원 ID 추가 | 관리자가 팀원 ID 검색·추가 → 수락 절차 없이 즉시 등록 | 존재하지 않는 ID / 이미 추가된 팀원은 오류 안내. `(meeting_id, user_id)` 복합 유니크 | 상 |
| MEET-04 | 자동 매칭 즉시 실행 | 팀원 추가 즉시 공강 재연산 | 추가와 동시에 Top 3 결과 생성·출력 (`trigger_type = 참여`) | 상 |
| MEET-05 | 권한 위임·모임 탈퇴 | 관리자 권한 위임, 모임 탈퇴 | 관리자 1명 제한. 위임 전 관리자 탈퇴 불가(모임 삭제는 가능). 위임은 **두 role 변경을 한 트랜잭션**으로 | 중 |
| MEET-06 | 모임 메모 | 공지·공유 메모 작성/수정/삭제 | 작성자·작성 시각 저장. 수정·삭제 권한은 작성자 본인 + 관리자 (→ §14-6) | 하 |
| MEET-07 | 모임 삭제 | 관리자만 삭제 (Soft Delete) | 비관리자 요청 서버에서 차단 | 상 |

### 7.4 공강 매칭 (MATCH)

| ID | 요구사항 | 상세 | 수용 기준 | 우선 |
|---|---|---|---|---|
| MATCH-01 | 비트 연산 공강 탐색 | 팀원 전체 비트 벡터 AND → 공통 공강 | O(N) 연산, 인원 증가에도 **수 초 이내** | 상 |
| MATCH-02 | 최적 후보 Top 3 | 이동 여유시간·최소 회의시간 반영해 최대 3개 추천 | 최소 회의시간 미만 구간 자동 제외. 묶음 내 `rank_no` 중복 불가 | 상 |
| MATCH-03 | 차선책 제시 | 공통 공강 0건 시 최대 인원 참석 가능 구간 추천 | 시스템 멈춤 없이 '전원 참석 불가' 사유 안내 + 차선 후보(`set_type = 차선책`, `reason` 기록) | 상 |
| MATCH-04 | 연산 이력 관리 | 실행 당시 조건 스냅샷·시간표 상태 기록 | 결과 덮어쓰기 금지, 이력 누적. `input_hash` 비교로 재계산 필요 여부 판별 | 중 |
| MATCH-05 | 관리자 수동 재계산 | 시간표 변경 등으로 `needs_recalc = true`일 때 관리자가 재실행 | 관리자 권한 확인. 재계산 시 기존 묶음 폐기 + 새 묶음 생성, 이전 투표는 기존 묶음에 보존 | 상 |
| MATCH-06 | 참석률 컬러맵 | 시간대별 참석 가능 인원을 색 농도 + 숫자로 표시 | **전체 구성원 수 / 시간표 입력 인원 수** 함께 표시. 색상 ↔ 실제 인원 일치 | 상 |

### 7.5 투표 · 일정 확정 (VOTE)

| ID | 요구사항 | 상세 | 수용 기준 | 우선 |
|---|---|---|---|---|
| VOTE-01 | 후보 선호 투표 | 추천/차선 후보 중 선호 시간 선택 또는 '참석 가능 후보 없음' 제출 | 후보 묶음당 **1인 1투표지** (`(set_id, member_id)` 유니크). 다른 묶음 후보 선택은 **복합 FK로 DB 단계 차단**. '후보 없음' = 선택 항목 0건. 미응답 ≠ 후보 없음 | 상 |
| VOTE-02 | 실시간 집계·최종 후보 도출 | 투표 결과 실시간 집계 | 동률 시: **참석 가능 인원수 > 검색 조건 부합도** 순 | 상 |
| VOTE-03 | 최종 확정 | 관리자가 최종 후보로 확정 | 확정 직전 최신 시간표로 **재검사**(`trigger_type = 확정 전 재검사`), 결과를 `recheck_run_id`로 기록. 변경 감지 시 Top 3 재계산 제안. **모임당 확정 일정 최대 1개** | 상 |
| VOTE-04 | 외부 공유 | 확정 일정 공유 링크(`share_token`) | 비회원 접근 시 읽기 전용 시각화. **개인 상세 시간표는 미포함** | 중 |
| VOTE-05 | 확정 후 충돌 표시 | 확정 이후 시간표 변경으로 충돌 발생 | 일정 상세 화면에 '재확인 필요' 상태 표시 | 중 |

## 8. 비즈니스 규칙 (핵심 정리)

1. **미등록 ≠ 전원 가능** — `timetable_registered_at IS NULL`이면 '미입력' 표시, 매칭에서 '가능'으로 계산 금지
2. **등록 후 0건 = 전원 공강** — 정식 비트 벡터(모두 1)로 생성
3. **재계산은 관리자가** — 시간표 수정은 `needs_recalc` 플래그만 세우고, 실제 재계산은 관리자 실행 (단, 팀원 추가 시는 자동)
4. **계산은 이력으로** — `MATCHING_RUN`은 덮어쓰지 않고 누적, 최신 결과는 `(meeting_id, calculated_at)` 인덱스로 조회
5. **재계산 = 새 투표 라운드** — 기존 `CANDIDATE_SET`은 폐기, 이전 투표는 보존
6. **확정 여부 판단** — 별도 상태 컬럼 없이 `CONFIRMED_SCHEDULE` 존재 여부로 판단
7. **불참 인원** = `MATCHING_RUN.total_member_count − CANDIDATE.available_count`
8. **참석 가능 인원 ≠ 득표수** — 두 값을 혼동하지 않음
9. **삭제는 Soft Delete** — USER, MEETING, MEETING_MEMO는 `deleted_at` 사용
10. **권한은 서버에서 검증** — 초대 유효성, 중복 가입, 비멤버 접근, 권한 없는 일정 변경 모두 서버 차단

## 9. 매칭 알고리즘 명세

### 9.1 시간 모델
| 항목 | 값 |
|---|---|
| 범위 | 월~금, 09:00~21:00 |
| 슬롯 단위 | 30분 |
| 슬롯 수 | 5일 × 12시간 × 2 = **120슬롯 (120비트)** |
| 저장 단위 | 64비트 워드 2개 (남는 8비트는 계산에서 제외 — 마스킹) |
| 비트 의미 | 1 = 참석 가능, 0 = 불가능 |

### 9.2 처리 순서
```
1. 일정 → 불가능 구간 산출
2. 이동 여유시간(travel_buffer_min) 만큼 불가능 구간 앞뒤 확장
3. 구간 → 120비트 벡터 변환 (구성원별)
4. 시간표 미등록자 제외 처리 / 안내
5. 전원 벡터 워드 단위 AND → 공통 가능 비트열
6. 연속된 1 구간 추출 → 길이 ≥ min_duration_min 인 구간만 후보
7. 정렬 후 Top 3 → CANDIDATE_SET(일반 추천)
8. 후보 0건이면 → 슬롯별 가능 인원 집계 → 최대 인원 구간으로 차선책 SET 생성
```

### 9.3 복잡도
| 방식 | 비용 |
|---|---|
| 슬롯 단위 비교 | O(N × S) |
| 워드 단위 AND | O(N × ⌈S/w⌉) — S=120, w=64 → 구성원당 워드 2개 |
| S 고정 시 | 둘 다 O(N), 단 실제 연산량은 비트 방식이 크게 적음 |

> 전체 응답 시간에는 입력 변환·후보 추출·DB 조회·렌더링 비용이 별도로 포함됨 → 핵심 연산 시간과 UI 응답 시간을 **분리 측정**

### 9.4 미확정 사항 (상세설계 이후 결정 필요)
- 슬롯 경계에 맞지 않는 시각 처리 (예: 10:15 종료) — **제안**: 불가능 구간은 바깥쪽으로 올림/내림(보수적 처리)
- Top 3 정렬 점수 함수 (구간 길이? 시작 시각 선호? 요일 분산?)
- 컬러맵/차선책용 슬롯별 인원 집계 방식 (popcount vs 슬롯 순회)
