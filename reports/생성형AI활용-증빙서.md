# 생성형 AI 활용 서면 증빙서

> 원본: [`생성형AI활용-증빙서.pdf`](./생성형AI활용-증빙서.pdf)
> 생성형 AI 활용이 조건부 허가된 교과목의 과제(보고서) 제출 시 함께 제출하는 증빙 문서.

## 1. 사용한 AI 정보(일시)
ChatGPT, Codex, ASTRA Medium — 2026년 10월 7일, 2026년 10월 12일

## 2. 활용 목적 및 범위
TEUM의 **클래스 다이어그램 초안 생성·수정**, 클래스별 담당·속성·기능 정리, 클래스 간 관계 및 UML 표기 이해를 위해 생성형 AI를 활용하였다. 클래스 다이어그램 강의 자료, ERD 이미지, 유스케이스 이미지와 보고서 양식을 참고 자료로 제공하였다. 소셜 로그인, 시간표 이미지 업로드·직접 입력, 팀원 초대, 공강 자동 계산, 추천 시간대 투표, 관리자 수동 재계산이라는 **사용자 흐름은 직접 제시**하였다.

## 3. AI 대화 내용 요약

- **[질문 1]** 클래스 다이어그램 강의 자료 기준으로 TEUM의 클래스 다이어그램 생성 요청. 엔터티 이름·속성명은 ERD와 동일하게 유지, 제시한 사용자 흐름 반영 요구.
  - **[답변 1]** USER, TIMETABLE_SLOT, MEETING 등 **11개 클래스**를 구성하고 속성·메서드·연관 관계·복합 관계·다중성을 포함한 이미지 생성. ERD에 초대 대상·미수락 상태 저장 구조가 없어 전원 수락 판정을 위해 보완 필요하다고 설명.
- **[질문 2]** 각 클래스의 담당 역할·속성·기능을 보고서에 작성할 수 있도록 설명 요청.
  - **[답변 2]** 사용자, 시간표 항목, 모임, 구성원, 메모, 계산 이력, 후보 집합, 후보, 투표 응답, 선택 항목, 확정 일정의 역할·속성 의미·메서드 기능 정리.

## 4. 단계별 비판적 검증 요약

- **[문제점]** 초기 다이어그램에 ERD의 `bigint`, `tinyint`, `varchar` 등 DB 자료형이 그대로 사용되어 Java 기준 상세설계 표현과 차이.
  - **[학생 주도 수정]** Java 기준 재작성 요구. 엔터티 이름·속성명은 유지하면서 속성·반환타입을 Java 자료형으로 변경.
- **[문제점]** 초기 설명이 시간표 항목·후보가 특정 객체에 속한다는 점만 강조해 복합 관계의 핵심인 소유·생명주기 종속 조건이 충분히 드러나지 않음.
  - **[학생 주도 수정]** USER–TIMETABLE_SLOT, CANDIDATE_SET–CANDIDATE를 복합 관계로 표현한 이유를 질문. 단순 소속만으로 복합 관계를 결정할 수 없으며 삭제·이력 보존 정책까지 고려해야 함을 확인.
