## 요약문

대학생의 팀 프로젝트 및 스터디 모임에서 발생하는 일정 조율의 번거로움을 줄이기 위한 웹 기반 공강 시간 탐색 서비스 '틈(Teum)'의 개념설계를 목적으로 한다. 시간표를 개별적으로 공유하고 수작업으로 비교하는 과정의 비효율을 개선하기 위해, 기존 시간표 데이터를 활용하고 필요한 내용을 직접 입력·수정할 수 있는 방식을 설계한다. 핵심 기능은 시간표 입력 및 저장, 모임 생성과 참여, 공통 참석 가능 시간 탐색, 결과 시각화, 최종 일정 확정 및 조회로 구성한다. 시간표는 일정한 시간 단위의 비트열로 표현하며, 비트 연산을 통해 구성원들의 공통 가능 시간을 계산하고 이동 여유 시간과 최소 회의 시간을 반영하여 후보 시간대를 도출한다.

## 1. 서론

### 가. 목적
대학생 그룹을 대상으로 팀원 각자의 강의 시간표를 분석하여 조건을 만족하는 공통 참석 가능 시간대를 자동 추천하는 웹사이트 '틈(Teum)'을 설계한다.

### 나. 주안점
시간표를 시간 구간의 집합으로 모델링하고 이를 비트 연산으로 치환해 계산 비용을 낮추는 동시에, 이동 버퍼와 최소 회의 시간 등 현실적 제약조건을 알고리즘에 반영한다.

### 다. 설계 추진 및 관련자
- **설계 추진 주체:** 설계 프로젝트 5팀
- **지원 주체:** 팀프로젝트1 김상귀 교수님
- **주요 사용자:** 팀 프로젝트, 전공 스터디, 동아리 등 회의 시간 조율이 빈번한 대학생 그룹
- **기타 관련자:** 향후 개인 일정 연동을 위한 외부 캘린더 API 제공자

### 라. 팀 구성 및 역할
팀명 **Finder** (5명). 상세 역할은 [팀원 명단](../notes/팀원-명단.md) 참고.

| 이름 | 역할 |
|---|---|
| 한규진 (팀장) | 프로젝트 총괄(PM), 요구사항 정의 및 제안서 작성, 전체 시스템 구조 설계 지원 |
| 송하성 | 사용자 요구사항 분석(설문), 웹 UI/UX 인터페이스 설계 및 입력 환경 구현 |
| 이다인 | 핵심 시간표 매칭 알고리즘 설계 및 점수 함수 연산 모델링 |
| 전기헌 | 사용자 시간표 데이터 입·출력 처리부(CSV/비트 변환기) 구현 및 성능 검증 |
| 현고은 | 선행 서비스 분석·비교 조사, 시스템 통합 테스트케이스 작성 및 보고서 작성 |

### 마. 필요성 / 시장성 / 기대효과
단체 채팅방에 시간표를 캡처해 눈으로 대조하는 수작업 방식이나 "When2meet" 같은 단순 공유 도구는 이미 확정된 시간표를 다시 옮겨 적는 **이중 입력**의 번거로움과 정보 누락·일정 충돌·의사소통 지연 문제를 가진다. '틈(Teum)'은 기존 시간표 데이터의 재활용성과 자체 알고리즘 추천을 결합한 대안을 제시하여 일정 조율 시간 단축을 1차 목표로 한다.

## 2. 아이디어 창출

브레인스토밍으로 기능을 **5개 영역**으로 구분: 핵심 일정 매치, 그룹(모임방) 관리, 그룹 소통 및 의사결정, 일정 확정 및 연동, 사용자 계정 및 프로필. 도출 아이디어는 마인드맵으로 관계를 정리하였다.

## 4. 아이디어 최종 선택

**투표 방식:** 팀원당 20표, 하나의 아이디어에 최대 2표. 3표 이하 기능은 회의 후 최종 선택.

**선정된 아이디어:** 소셜 로그인, 로그아웃, 프로필(시간표 저장용), 시간표 입력(자동/수기), 시간표 자동 매칭, 참석률 시각화(컬러맵), 차선책 안내, 선호 시간 투표, 메모, 알림, 모임 생성/수정/삭제, 초대 링크/코드 생성, 모임 탈퇴, 최종 일정 확정, 외부 캘린더 내보내기, 결과 화면 이미지/링크 공유.

> 선호 시간 투표·세부 멤버 권한은 **설계까지만**, 차선책 안내·알림·외부 캘린더 내보내기는 **향후 확장**으로 둔다. 관리자·일반 멤버 기본 권한 구분은 이번 학기 구현.

### 기능 설계/구현 계획 (요지)
- **구현 범위:** 한 학기 내 웹 기반 시제품. 핵심 흐름 = 로그인 → 시간표 등록 → 모임 생성·참여 → 공통 참석 가능 시간 탐색 → 최종 일정 확정 및 조회.
- **시간표 입력·변환:** 주간 반복 강의 기준 등록, 개인 일정 추가 가능. 기존 데이터 가져오기는 CSV 우선 검토, 미지원 자료는 직접 입력으로 보완. 미입력자는 '미입력' 상태로 표시(전원 참석 가능으로 간주하지 않음).
- **공통 참석 가능 시간 탐색:** 슬롯 비트화(가능 1/불가 0) → 이동 여유 시간 반영 → AND 연산으로 공통 슬롯 도출 → 연속 슬롯을 구간으로 묶어 최소 회의 시간 이상만 후보 제공.
- **결과 시각화·확정:** 시간대별 참석 가능 인원을 색·숫자로 표시. 관리자가 후보 선택·확정, 확정 직전 최신 시간표로 재검사. 공유는 링크 우선.
- **개발 일정(12주):** 1~2주 요구사항·범위 확정 / 3~4주 설계 / 5~7주 핵심 구현 / 8~9주 시각화·확정 통합 / 10~11주 검증·수정 / 12주 시연·보고서.
- **검증·완료 기준:** 전체 사용자 흐름 기준 기능 검증, 매칭 알고리즘은 정답 사례와 비교. 정상 동작 + 오류 처리 + 권한 검증 통과 시 완료로 판단.
