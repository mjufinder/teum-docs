## 01. 프로젝트 목적·기대효과
- 문제: 시간표 캡처 공유·눈 대조, When2meet 이중 입력, 정보 누락·충돌·지연.
- 목표: 기존 시간표 재활용으로 조율 시간 단축, 공통 시간 추천·투표·재검사로 최종 일정 확정.

## 02. 제한조건
관리적(5명·12주, 단계별 일정) / 시스템적(DB 도입, 웹 기반 이미지+수기 입력, 120비트 규격화, 성능 최적화). 상세는 [보고서 §2](./진행보고서-상세설계.md#2-현실적-제한조건).

## 03. 유스케이스 · ERD · 클래스 설계

### 유스케이스 — 세 역할로 읽기
| 역할 | 할 수 있는 일 |
|---|---|
| 사용자 | 로그인·프로필·시간표·모임 생성/참여 |
| 모임 구성원 | 메모·투표·결과 조회·공유 |
| 모임 관리자 | 모임 관리·재계산·최종 확정 |

### 유스케이스 흐름 (3명이 팀 회의 시간을 정하는 예시)
1. **준비** — 로그인 후 각자 강의 시간표·개인 일정 입력
2. **참여** — 관리자가 모임·초대 생성, 구성원 참여
3. **추천** — 시간표 자동 매칭 후 최대 3개 후보 제시
4. **선택** — 구성원이 추천 후보에 선호 투표
5. **확정** — 관리자가 최신 시간표 재검사 후 최종 일정 확정

> include: 수행에 포함되는 기능 / extend: 특정 조건에서 추가되는 기능. 관계선은 실행 순서가 아님.

### ERD · 클래스 다이어그램
11개 엔터티/클래스(USER, TIMETABLE_SLOT, MEETING, MEETING_MEMBER, MEETING_MEMO, MATCHING_RUN, CANDIDATE_SET, CANDIDATE, VOTE_BALLOT, VOTE_SELECTION, CONFIRMED_SCHEDULE)의 필드·관계·다중성은 [보고서 §3](./진행보고서-상세설계.md#3-설계-결정-진행-상황) 참고.

## 04. 비트 벡터·시간복잡도·애자일
- 주간 120슬롯 비트 벡터 + 워드 단위 비트 AND → 공통 공강 O(N).
- 애자일 MVP(개인·상호작용, 우선순위 반복, 빠른 피드백, 변화 대응).

## 05. 설계 평가·다음 단계
- 평가: 알고리즘 성능·정확도, 예외·차선책, 데이터 무결성·변환, 활용성.
- 다음 단계: DB·API 명세 확정, 사용자·모임 관리, 시간표 입력·변환, 매칭, 투표·확정, 시각화, 검증.
