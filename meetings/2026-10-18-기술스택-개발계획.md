# 프로젝트 기술 스택 및 개발 계획 회의

- **참석자:** 기현, 하성(프론트), 다인, 고은(백엔드), 규진(문서)

## 개요

프로젝트의 기술 스택과 개발 방식, 요구사항·API 명세서 작성 일정, 역할 분담을 논의했다.
10월 20일 제작 보고서 멘토링을 앞두고 요구사항 명세서를 정리하고 개발 환경을 준비하기로 했다.

## 참석자 및 역할

- **기현, 하성:** 프론트엔드 담당 예정
- **다인, 고은:** 백엔드 담당 예정
- **규진:** 기존 기능 자료를 바탕으로 문서를 정리하고 주말에 수정본을 공유하기로 함

## 결정 사항

- **프론트엔드:** React 기반 **Next.js**
- **백엔드:** 비트맵 연산 구현 가능성을 고려해 **Python FastAPI** 사용
- **데이터베이스:** 무료 이용과 소셜 로그인 지원을 고려해 **Supabase** 사용. PGVector 지원도 장점으로 언급됨
- **배포:** Next.js와 연동이 간편한 **Vercel** 사용
- 기능을 모듈 단위로 나눠 개발하고, 완성된 모듈과 인터페이스를 서로 공유한다.
- API 명세서는 개발을 시작하면서 함께 작성한다. 백엔드 모듈 구현 후 명세를 공유해야 프론트엔드 연동이 가능하다.

## 실행 항목 (Action Items)

- **요구사항 명세서 담당자:** 기존 자료를 기반으로 명세서를 주말까지 검토·수정하고, 변경 사항과 함께 단체 채팅방에 공유
- **프론트엔드 담당자:** 개발 브랜치에서 바로 작업할 수 있도록 Next.js 기본 환경을 준비
- **백엔드 담당자:** FastAPI를 익히고 개발 준비. 시험 일정 등을 고려하되 가능한 한 다음 주 중 개발 착수 목표
- **백엔드·프론트엔드 담당자:** 모듈별 진행 상황과 API 정보를 수시로 공유
- **팀:** 10월 20일 멘토링에 앞서 기술 스택과 요구사항 명세서를 정리

## 논의 사항

- 기존 기능 선정 자료를 활용하면 요구사항 명세서를 효율적으로 작성할 수 있으며, 초안은 AI를 활용해 만들고 필요한 내용을 수정하기로 했다.
- FastAPI는 일부 참석자가 사용 경험이 없지만, 단순 CRUD 중심이라 학습 부담이 비교적 낮을 것으로 기대했다. 비트맵 연산 구현이 가능한 점도 선택 근거로 고려했다.
- Next.js와 FastAPI 연동은 일반적인 웹 구조처럼 API 요청을 보내는 방식이므로 큰 문제가 없을 것으로 보았다.
- API 명세서 작성과 테스트에는 Postman 또는 API 문서·테스트 도구를 활용할 수 있다.
- 시험 일정이 있어 학습 및 개발 착수 시점은 조정이 필요하지만, 다음 주 중 개발에 들어가는 것을 목표로 한다.
