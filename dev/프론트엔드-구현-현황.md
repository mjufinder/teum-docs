## 2. '부분' 항목과 명세와 다른 점

- **TIME-02** — 명세는 요일·수업 시간·**과목명**을 입력하는 방식이지만, 현재는 **칸을 눌러 칠하는 방식**이라 과목명을 받지 않습니다. 저장 형식(비트열)에도 과목명이 없습니다.
- **TIME-03** — 명세는 주간 **120개** 슬롯이지만 실제 구현은 **182개**(7일 × 26칸, 09:00~22:00)입니다. 프론트·백엔드가 182 로 맞춰져 있어 동작에는 문제가 없으나, 문서와 차이가 있습니다.
- **VOTE-02** — 집계는 화면을 열거나 내가 투표했을 때 갱신됩니다. 다른 팀원의 투표가 **자동으로 반영되지는 않습니다** (새로고침 필요).
- **VOTE-03** — 확정 직후에는 확정 시간이 표시되지만, **화면을 다시 열면 확정된 시간을 알 수 없습니다** (조회 API 없음, 아래 3번 참고).

## 3. 백엔드 요청 사항

프론트 화면을 완성하려면 아래 API 또는 응답 항목이 필요합니다.

| 요청 | 필요한 이유 | 관련 요구사항 |
| --- | --- | --- |
| 확정 일정 조회 API | 화면을 다시 열어도 확정된 시간을 보여 주기 위해 | VOTE-03 |
| 내 투표 조회 API | 내가 이미 고른 후보를 다시 열었을 때 표시하기 위해 | VOTE-01 |
| 추천 다시 계산 API | 지금은 팀원을 추가할 때만 계산됨. 시간표·조건이 바뀐 뒤 직접 다시 계산할 방법이 필요 | MATCH-04 |
| 팀원 응답에 이름 포함 | 지금은 '팀원 2'처럼 번호로만 표시됨 | MEET-03 |
| 팀원 전체 시간표(겹침) 조회 API | '한 주에서 보기'에 추천 구간뿐 아니라 팀 전체의 빈 시간을 겹쳐 보여 주기 위해 | MATCH-02 |
